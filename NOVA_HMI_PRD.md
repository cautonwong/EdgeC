## Problem Statement

Industrial edge devices and SCADA systems typically suffer from outdated, utilitarian user interfaces that fail to visualize complex, high-frequency mathematical data (like FFT spectrums, Kalman Filter states, or MPC prediction horizons). As EdgeC evolves into a high-performance mathematical brain capable of sub-millisecond control and radar signal processing, operators and engineers lack a "window" into the engine. Traditional web dashboards lag when rendering 10kHz data streams, resulting in a disconnected user experience that undermines the premium value of the underlying C engine.

## Solution

The EdgeC "Nova" HMI (Human-Machine Interface) is a next-generation, high-performance UI frontend. It abandons generic dashboard templates in favor of a bold, "Industrial Sci-Fi" / "Cyber-Physical" aesthetic. It leverages WebSockets (`ws_proto.c`) for real-time telemetry from the `DataHub`, and utilizes WebGL/Canvas on the frontend to render dense data arrays (like FMCW Radar Range-Doppler maps and Wavelet anomaly spikes) at 60 FPS. This transforms the EdgeC gateway from a headless box into a premium Digital Twin appliance.

## User Stories

1. As a **plant operator**, I want a visually striking, dark-themed industrial dashboard, so that I can immediately grasp the overall health of the microgrid or robot cell in low-light environments.
2. As a **radar engineer**, I want to view a real-time, 60 FPS heatmap of the 2D-FFT Range-Doppler array, so that I can visually verify CFAR target detection without connecting external lab equipment.
3. As a **control theorist**, I want to see a live trajectory chart comparing the EKF estimated State-of-Charge (SOC) versus the raw BMS readings, so that I can trust the mathematical noise filtering.
4. As a **system administrator**, I want the frontend assets to be served directly from the EdgeC embedded `web_server.c`, so that I don't need a separate cloud server to view the local HMI.
5. As an **automation integrator**, I want an interactive topology graph of the active `StreamEngine` pipeline, so that I can visually trace how data flows through filters, math operators, and sinks.

## Implementation Decisions

- **Aesthetic Direction**: "Utilitarian Cyber-Physical". Dark backgrounds (e.g., `#0a0a0c`), sharp neon accent colors (cyan, electric green, hazard orange) for data series, monospace technical typography (e.g., JetBrains Mono or Fira Code) for numbers, and precise grid-based spatial composition. No generic rounded-corner white-card "SaaS" aesthetics.
- **`module: ui_telemetry_streamer` (Backend)**: Extend `ws_proto.c` to support bulk array subscriptions. Instead of sending JSON for every single array element, it will pack 2D-FFT or Wavelet buffers into binary WebSocket frames to prevent CPU/Network overhead.
- **`module: nova_core_app` (Frontend)**: A modern frontend framework (React or Vue) utilizing Vite for build tooling. The build output will be minimized and placed into the EdgeC `web/` directory for the C server to host.
- **`module: canvas_spectrum_viewer` (Frontend)**: A custom WebGL or HTML5 Canvas React component dedicated to rendering dense arrays (FFT, DWT, Radar point clouds) bypassing the DOM for performance.
- **`module: stream_topology_graph` (Frontend)**: An interactive, SVG or Canvas-based node graph visualizing the EdgeC semantic contracts and pipeline stages.

## Testing Decisions

- **High-Frequency Rendering Test (AFK)**: We will simulate a 1kHz data stream from the backend and assert that the frontend Canvas component maintains 60 FPS without memory leaks in the browser.
- **Binary WebSocket Decoding Test (AFK)**: Ensure the JavaScript frontend correctly unpacks the little-endian/big-endian binary payloads generated by the C backend.

## Out of Scope

- Cloud-hosted aggregated dashboards (Nova HMI is strictly local/edge-first).
- 3D CAD model rendering of physical robots (stick to data-driven 2D charts and topologies).
