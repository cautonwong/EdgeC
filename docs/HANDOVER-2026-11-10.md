## 2. 本轮目标

目标是把 EdgeC 从按产品堆叠的代码库，推进为**可复用的 components-based 大型 monorepo**：

- 组件只保留自己的领域逻辑和稳定契约
- 传输、持久化、平台、产品适配器放到 `adapters/`
- 组合根只负责生命周期和装配
- 公开 API、会话、算法子域独立成组件
- 用架构门禁、组件元数据和本地 CI 防止边界回退

## 3. 目录与组件现状

### 3.1 顶层分层

| 目录 | 职责 |
|---|---|
| `foundation/` | 纯公共代码：数学、编解码、缓冲区、加密 ops、公共类型、端口值对象 |
| `modules/` | 领域组件和 bus/stream/north 等核心组件 |
| `adapters/` | REST、MQTT、DataHub bridge、SQLite、驱动、Linux 平台、算法流适配器 |
| `cmd/` | 产品组合根和产品专属代码：iEMS、DCU、SmartBox、MCP Server、Nexus Lab |
| `web/` | WebUI、mock server、Playwright E2E |
| `tests/` | 单元/集成测试和架构 guard fixture |
| `acceptance/` | test-platform 验收任务和 WebUI 验收 |
| `ci/` | guard 脚本、baseline、sanitizer/裁剪配置 |

### 3.2 主要模块

| 组件 | 状态 |
|---|---|
| `edge_core` | DataHub、service、参数、arbiter 等核心运行时 |
| `edge_infra` | 存储、DDS、NPU、遥测等基础设施实现 |
| `edge_infra_security` | license、ESAM、SOS/DSCP、Edge-Guard DPI |
| `edge_io` | 主站/从站 bus 编排、引擎、协议桥、调度和 guard port |
| `edge_session` | 从站会话管理和驱动实例生命周期 |
| `edge_stream` | 流计算 DAG、标准 stage、WASM 调度 |
| `edge_north` | 北向传输、SnF、协议无关编排 |
| `edge_api` | 产品级读/写/原始 IO 门面 |
| `edge_mgmt` | App 管理、console、审计等管理面 |
| `edge_mcp` | MCP 通用工具 dispatcher 和工具端口 |
| `edge_ai` | AI 推理、量化、tensor pool、PINN |
| `edge_battery` | 电池建模、EIS、SOH、均衡、热管理 |
| `edge_health` | ECG/PPG/EMG、康复、步态、跌倒、DICOM |
| `edge_power` | VSG、FFR、黑启动、预同步、场站协调 |
| `edge_runtime` | CEP、WASM NN、算子融合、ONNX guard、联邦聚合 |

`modules/edge_algo` 已删除，不再有兼容聚合层。原来链接 `edge_algo` 的代码现在显式链接上述五个算法子组件。

### 3.3 适配器

| 适配器 | 内容 |
|---|---|
| `adapters/rest_api` | REST server、web server |
| `adapters/mqtt_transport` | MQTT producer、edge_agent |
| `adapters/datahub_bridges` | stream/protocol/north/radar/ADC/js-arbiter/MCP 到 DataHub 的桥 |
| `adapters/sqlite_adapters` | app repo、stream、SnF、params、persistence 的 SQLite 实现 |
| `adapters/io_drivers` | 协议驱动和 driver manager |
| `adapters/linux_platform` | Linux io_executor、TSN、BSP HAL |
| `adapters/stream_algo` | 算法输出端口到 stream/DataHub 的适配 |
| `adapters/edge_ports` | consumer port 实现 |
| `adapters/mcp_industry` | 行业 MCP 工具包和 Provider |

### 3.4 关键边界

- `edge_bootstrap/src/edge_composition_root.c` 是共享组合根，只做装配。
- `edge_io` 不再直接链接 SQLite、MQTT agent、web server 或 Linux 平台实现。
- `edge_session` 通过 `driver_instance_create` 装配驱动实例，已登记为受控组合根。
- `edge_slave_plane.h`、`edge_algo_port.h`、`edge_port_types.h` 等端口值类型在 `foundation/include`。
- 组合根注入 Edge-Guard DPI port；DPI 未初始化时 `dpi_validate_telemetry` 返回 PASS。
- 所有 `modules/*` 和 `adapters/*` 必须有 `component.meta`。

## 4. 本轮主要工作

### 4.1 早期架构修复

- 修复 iEMS CLI attach DataHub shadow 时覆盖运行中节点的问题：
  - 新增 `datahub_attach`，只打开已有段，不创建/截断

  - 增加 `test_datahub_attach` 回归测试

- 收紧 SRP 守卫，支持多行签名和花括号配对。
- 将六个架构账本清零：
  - PLANE_ISOLATION
  - AGGREGATE_BOUNDARY
  - COMPOSITION_ROOT
  - OCP_PLUGIN
  - ZERO_DYNAMIC_MEMORY
  - STACK_USAGE
- 组合根预算和 caller-allocated storage 继续使用 shrink-only baseline。

### 4.2 组件化与适配器化

- `edge_api` 从 `edge_io` 拆出。
- `edge_session` 从 `edge_io` 拆出。
- REST、MQTT agent、web server、SQLite persistence 移入 `adapters/`。
- DataHub router 三后端改为表驱动。
- MCP 工具访问改走组件自有 `edge_mcp_tool_port_t`，不再暴露 `pipe_msg_t`。
- `edge_mcp` 不再链接 `edge_core`。
- `edge_stream` 去除 `edge_algo`/`edge_core` 直接依赖。
- `edge_north` 独立，SnF 通过 `snf_store_port_t`。
- `edge_mgmt` 使用自有 logger port。
- app repo、params、SnF、control port 都通过端口/适配器注入。
- `adapters/linux_platform` 承载 Linux io_executor、TSN、BSP HAL。
- `edge_bootstrap` 最终只保留组合根。

### 4.3 算法子域拆分

按领域拆分 `edge_algo`：

- `edge_ai`
- `edge_battery`
- `edge_health`
- `edge_power`
- `edge_runtime`

拆分完成后删除 `modules/edge_algo`。`EDGEC_ALGO_LINALG`、`EDGEC_ALGO_DSP`、`EDGEC_ALGO_AHRS`、`EDGEC_ALGO_VIBRA` 选项迁到 `foundation/Kconfig`，避免干净配置时丢失线性代数源文件。
