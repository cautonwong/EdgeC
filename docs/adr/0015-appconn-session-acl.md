# ADR 0015: 698 应用连接（Class 20）的会话状态与对象表 ACL

## 状态

Proposed（2026-11-22，待架构评审）。

## 上下文

Class 20 应用连接对象（7.3.20 表181/182/183）把"可访问对象 + 每属性/每方法权限"定义为一个对象列表。标准 6.1.1.3.2 要求同一客户机同时只有一个应用连接，同一客户机重复 CONNECT 时旧连接失效；6.1.1.3.3 允许预连接窗口（最低权限，由服务器定义）。

现状：`dlt698_req_slave_exchange` 的 `session` 参数被忽略，`ctx_size = 0`，所有 OAD 一律放行。

## 决策

### 1. 会话状态放在驱动 ctx 的 `priv`

`edge_driver_t.ctx_size = sizeof(dlt698_session_t)`；`driver_manager` 已有 `DRIVER_PRIV_SIZE`（1024 B）定长存储并按会话清零。会话里只放：是否已连接、客户机地址、以及从对象列表解析出的 ACL。无动态内存；ACL 数组有上限，超出上限视为"对象列表不可用"，不截断。

### 2. 对象列表经既有 `resolve_axdr` 端口取，不新增端口

驱动在 CONNECT 时（以及首次数据请求时的预连接窗口）调用
`src->resolve_axdr(ctx, 0x44000200, buf, cap, &len)`，由产品的 Class 20 对象返回属性 2 的原始 A-XDR（表182 结构）。驱动用自己的 698 解析器把它转成定长 ACL。

- 端口仍协议中立：`edge_slave_plane.h` 不出现 RSD、对象列表结构或 DAR；产品实现用 698 类型构造字节。
- 对象列表是唯一事实来源；产品未实现该 OAD、回调为 NULL、或解析失败 → ACL 不可用，数据请求一律 DAR 3，**不静默放行**。

### 3. 授权判定

- 预连接：session 存在但尚未 CONNECT 时，按产品定义的对象列表（同一份 4400 属性 2）作为最低权限窗口。
- CONNECT 成功后：同一份列表装入当前会话，`connected = true`，客户机地址记入会话。
- RELEASE：清空会话 ACL 与连接标记。
- session 为 NULL、ACL 未加载或对象不在列表 → GET/SET/ACTION 回 DAR 3。
- 类 20 自身的属性 2（对象列表）允许在未连接时读取，否则主站无法得知窗口；这是标准 6.1.1.3.3 的预连接语义。

### 4. CONNECT 的诚实性

按表59/表60 与附录 H.2 的字节布局解析与应答。未知认证机制（[1]–[3]）、协议版本不匹配、对象列表不可用分别回 `ConnectResult` 的非 0 值：版本不匹配 5，其余 255；不返回"允许建立"。

## 后果

- DCU 的 `cmd/dcu/dcu_698_appconn.c` 提供 4400 属性 2 的字节；`dcu_north_resolve_axdr` 对 `0x44000200` 走该构造器。
- 现有北向验收（不先 CONNECT）走预连接窗口，只要对象在列表里就保持通过；不在列表里的 OAD 从此回 DAR 3，而不是"碰巧能读"。
- 每次 CONNECT 都重新取列表；同一产品里两个会话不共享 ACL。
- 对象列表超过 ACL 定长上限时 CONNECT 失败（255），不截断成"部分授权"。
