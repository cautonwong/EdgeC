## Problem Statement

Medical diagnostic equipment (e.g., ECG, EEG, multi-parameter patient monitors) requires sampling vital signs at very high frequencies to capture nuanced physiological events. These analog signals are inherently susceptible to extreme environmental electrical noise (e.g., 50/60Hz mains hum from surrounding hospital equipment). Pushing this raw, high-frequency data to the cloud for filtering and analysis introduces unacceptable latency for life-critical alarms, consumes excessive bandwidth, and raises severe patient data privacy (HIPAA/GDPR) compliance issues.

## Solution

The EdgeC Medical Diagnostics Controller (Med-Ctrl) brings hospital-grade signal processing directly to the patient's bedside. Embedded within the medical device, it utilizes the `Algorithm Lexicon` to run multi-stage Digital Signal Processing (DSP). It applies precision IIR Notch filters to eliminate mains hum, and utilizes the Haar Discrete Wavelet Transform (`dsp_dwt_haar`) to analyze transient anomalies in the QRS complex of an ECG. By extracting only clinical insights and alarms locally, Med-Ctrl ensures zero-latency alerting and guarantees that raw, high-resolution patient data never needs to leave the secure, local network.

## User Stories

1. As a **biomedical engineer**, I want the embedded controller to apply a real-time 50/60Hz IIR notch filter to the raw ECG ADC stream, so that powerline interference is cleanly removed before any diagnostic algorithms analyze the wave.
2. As a **cardiologist**, I want the device to utilize wavelet transforms to analyze the high-frequency components of an ECG signal, so that subtle, transient arrhythmias are detected and alarmed instantaneously.
3. As a **hospital IT security officer**, I want the edge device to anonymize and aggregate all telemetry data, pushing only state changes (RBE) and critical alarms to the central nursing station via a secure MQTT tunnel, so that we minimize our HIPAA exposure risk on the network.
4. As a **device manufacturer**, I want to define the DSP filtering chain via the EdgeC Semantic Contract (YAML), so that I can easily tweak filter coefficients for different international markets (50Hz vs 60Hz) without recompiling the core C firmware.

## Implementation Decisions

- **`module: dsp_notch_filter_stage`**: An extension of the standard IIR filter stage, specifically optimized to define and execute deep notch filters. It will reside early in the StreamEngine pipeline immediately following the `req_raw_io` ADC ingestion.
- **`module: ecg_anomaly_detector_stage`**: A dedicated clinical stage utilizing the `dsp_dwt_haar` capability. It buffers a rolling window of filtered ECG data, extracts the relevant detail coefficients corresponding to the QRS complex, and triggers a `PIPEMSG_TYPE_EVENT` alarm if morphological deviations are detected.
- **`module: hl7_fhir_exporter`**: An integration driver that formats the aggregated, anonymized insights generated by the `DataHub` into standard HL7 FHIR (Fast Healthcare Interoperability Resources) JSON structures for northbound transmission, rather than generic Sparkplug B payloads.

## Testing Decisions

- **Mains Hum Rejection Test (AFK)**: We will inject a synthetic ECG signal heavily corrupted by a 60Hz sine wave into the pipeline. The output of the `dsp_notch_filter_stage` will be asserted to have an attenuation of > 40dB at precisely 60Hz, while preserving the amplitude and phase of the 1-40Hz clinical band.
- **Arrhythmia Detection Validation (HITL)**: We will replay standard MIT-BIH Arrhythmia Database recordings through the `ecg_anomaly_detector_stage`. A domain expert (HITL) must verify that the stage's triggered alarms accurately correspond to the annotated premature ventricular contractions (PVCs) in the dataset.

## Out of Scope

- Developing the actual FDA-certified clinical diagnosis algorithms (EdgeC provides the DSP and mathematical primitives, the final clinical logic is proprietary to the manufacturer).
- Driving the physical LCD screens on patient monitors (this is handled by a separate UI processor).
