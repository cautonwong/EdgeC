# IEC 60870-5-104 协议深度指南

## 1. 协议本质：网络化的 SCADA 命脉

IEC 104 是 IEC 101 的网络版适配 (Network Access)。它取消了链路层的校验（依赖 TCP），引入了 **APCI (应用规约控制信息)** 来管理链路状态和流控。

### 1.1 帧结构 (APCI)
`0x68 | Len | C1 | C2 | C3 | C4` (固定 6 字节头)

*   **I 帧 (Information)**: `Bit0 = 0`。携带 ASDU，消耗 $N(S)$ 和 $N(R)$。全双工传输。
*   **S 帧 (Supervisory)**: `C1 = 0x01`。只确认，不发数据。用于防止对方 $k$ 窗口堵塞。
*   **U 帧 (Unnumbered)**: `C1 = 0x03`。
    *   `STARTDT`: 激活/确认链路。
    *   `TESTFR`: 心跳测试。
    *   `STOPDT`: 停止传输。

### 1.2 关键参数 (The Parameters)
*   **$k$**: 发送未确认最大帧数 (默认 12)。
*   **$w$**: 接收确认阈值 (默认 8)。接收方每收到 $w$ 个 I 帧，必须回一个 S 帧。
*   **$t0$**: 连接超时 (30s)。
*   **$t1$**: 发送超时 (15s)。
*   **$t2$**: 无数据确认超时 (10s)。
*   **$t3$**: 长期空闲发送 TESTFR (20s)。

## 2. 落地现状与差距分析

### 已完成 (Done)
- [x] **APCI 状态机**: `iec104_apci.c` 实现了连接建立、STARTDT 握手、I/S/U 帧的构建。
- [x] **驱动集成**: `driver_iec104.c` 实现了主从双模，支持契约驱动的突发上报和总召唤。
- [x] **流式容错**: 实现了 `0x68` 滑动窗口搜索，具备从字节流错位中自愈的能力。
- [x] **Zero-Copy**: 利用 `net_buf_reserve` 实现了头部原地封装。

### 待开发 (TODO List)

#### 2.1 严苛的流控实现 (Flow Control)
- [ ] **$k$ 窗口阻塞**: 目前仅检查了 $k$ 值，但未实现“阻塞-等待-恢复”的完整挂起逻辑。如果窗口满了，Engine 应该暂停从 DataHub 取数。
- [ ] **$w$ 窗口确认**: 完善从站接收逻辑。每收到 $w$ 个 I 帧，自动触发发送 S 帧。目前代码主要依赖捎带确认。
- [ ] **重传队列 (Retransmission)**: `unacked_frames` 环形队列虽然已定义，但未在 $t1$ 超时后触发重发。需要实现：`on_t1_timeout` -> `resend_buffer`。

#### 2.2 复杂场景覆盖
- [ ] **双网冗余**: 思考如何在 `Bus Orchestrator` 层面支持 A/B 网热备（两个 TCP 连接对应一个逻辑设备）。
- [ ] **大包分拆**: 对于文件传输或超大 GI，实现基于 ASDU 的逻辑分包 (More segments to follow)。

## 3. 开发建议
优先攻克 **$w$ 窗口确认** 和 **$t1$ 重传**，这是通过一致性测试（如 KEMA 认证）的硬性指标。
